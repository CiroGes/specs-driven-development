# Acceptance Checklist

- Each criterion has a stable id (`AC<n>`) and exactly one observable behavior.
- Criteria use EARS (SHALL / SHALL NOT) or Given/When/Then — no soft verbs.
- Each criterion maps to at least one task (in `tasks.md`) and one verification
  row (in `acceptance.md`).
- No unresolved `[NEEDS CLARIFICATION]` markers remain.
- Scenarios include primary and edge flow.
- Non-goals avoid accidental scope expansion.
- Traceability links point to existing paths or planned paths.
